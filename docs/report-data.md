# 报告数据与展示

报告分为总结、技术细节、优化建议。在线页面与单文件导出共用 `report-view.js`、`report-rules.js` 和基础图表工具 `report-layout.js`。

- 总结先显示场景声明的首次响应，其次测量目标，未声明时保持原顺序。按钮数量来自结果数据。
- 平均、最快、最慢、中位数和P90由有效逐次记录计算。缺失值与负用时不作为零，异常原值保留在技术细节。整段用时取起终点记录；阶段先逐次合计连续分段，再求平均。
- 总结及技术细节的结果切换入口在滚动后保留紧凑栏，原卡片同时隐藏。技术页只在阶段与单次过程范围内固定，离开这部分后收起；选择同步更新统计、后续步骤及单次过程，共用步骤不随切换重画。
- 共用步骤要求相同的有向分段前缀。同起点、区间重叠的核对证据可以并排展示；相同数值不能证明共用步骤，也不能证明同一根因。
- 每个结果只和自己的参考值比较。参考要求为平均响应时间时，整组平均与参考值比较；单次超过仅作逐次标记。标准名称和档位同时核对来源、数值和统计口径。
- 内容相关结果可用 `content_dependent` 声明，兼容旧报告已有分类。完整结果与全部分段数值保留在技术页，移出总结不删除原始数据。

## 来源明确的语义

上游识别或导入结果可以携带可选的 `presentation`。网页不要求使用者手工填写，也不内置特定固件的代码位置或显示名称。没有已核对的阶段定义时，只按场景声明的设备内外边界分组，名称使用实际起终点。

`presentation.events.events` 保存源码位置 `at`、取值规则 `occurrence`（`first` / `last`）及该事件的解释。`presentation.phases.boundaries` 和 `resultNames` 通过同一键引用这些事件。只有当前场景中存在唯一匹配的源码位置、且首次/末次规则一致时，解释和显示名才会采用；更换点编号不影响匹配，更换绑定或存在歧义则回退到原名称。阶段定义可另带 `fromAt` 限定起点。

环境信息只读取报告实际携带的 `measurement_environment`：`rows` 为字段与值的列表，`details` 可保存更详细的标识和来源，`title`、`note` 可说明实际采集范围。没有保存的字段不补设备或版本示例，不把其他测试的环境当成本次环境。

## 建议与导出

建议沿用已有数据判定、模型分析和核对结果；没有有依据的方案时不凑类别或编造原因。方案选择、复制和研发处理细节在优化建议中，复测与还原仍使用运行中的码表入口。

下载数据保留完整报告载荷。保存报告内嵌样式、脚本和数据，可离线切换结果、展开记录、核对源码和逐次值；复测、模型重试、烧录还原等需要后台的操作不会在离线文件中伪装成可执行功能。
